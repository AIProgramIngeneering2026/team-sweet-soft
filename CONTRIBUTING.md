# Как мы работаем

Прямой push в `main` закрыт, все изменения попадают туда только через PR. Каждая задача начинается с issue, у которого есть исполнитель.

## Ветки

Формат: `<тип>/<номер-issue>-<кратко-латиницей>`

Типы:

- `feat`: новая функциональность
- `fix`: исправление ошибки
- `docs`: документация и требования
- `test`: только тесты
- `chore`: инфраструктура, CI, зависимости

Примеры: `docs/7-scenario-3`, `feat/12-runs-api`, `chore/15-github-actions`.

Одна ветка решает один issue. Ветку создаем от свежего `main`, после влития удаляем.

## Коммиты

Формат: `<тип>: <что сделано>`

Типы те же, что у веток. Описание пишем по-русски, в повелительном наклонении и без точки в конце, длиной до 72 символов.

```
docs: добавить сценарий 3 про синхронизацию с AI Arena
fix: вернуть 409 при отмене завершенного прогона
```

Один коммит содержит одно логическое изменение. Секреты и `.env` не коммитим, реплеи только тестовые наборы для автотестов.

## Pull request

- В описании указываем, что изменилось и как это проверить.
- Связываем с задачей строкой `Closes #<номер>`.
- Если работа еще не готова к review, открываем PR как Draft.

## Review

У каждого PR есть назначенный ревьюер:

| Автор PR | Ревьюер |
| --- | --- |
| СавенкоДР | БелослудцеваМН |
| ЯсеневНА | СавенкоДР |
| БелослудцеваМН | ЯсеневНА |

Если назначенный ревьюер не может посмотреть PR, его подменяет третий участник.

Правила:

- Для влития нужен минимум один approve. Свой PR не одобряем.
- Ревьюер отвечает в течение 24 часов после запроса review.
- В review должен быть хотя бы один вопрос или замечание по сути. Комментарии вроде «ок» и «TEST» не считаются. Если замечаний нет, пишем, что именно проверили.
- Обсуждение закрывает тот, кто его начал.
- Вливает автор после approve, через Squash and merge. Заголовок итогового коммита оформляем по правилам выше.

## Definition of Done

Задача сделана, когда выполнено все, что к ней относится:

- [ ] Выполнены критерии приемки из issue или `docs/requirements.md`.
- [ ] PR влит в `main` после approve, все обсуждения закрыты.
- [ ] Issue закрыт.
- [ ] Обновлена документация, которую задело изменение: README, требования, OpenAPI.

Дополнительно для задач с кодом:

- [ ] Новое поведение покрыто тестами, включая ошибочные случаи.
- [ ] `make test` проходит локально, проверки GitHub Actions зеленые.
- [ ] Ошибки API возвращаются в едином формате `{"error": {"code", "message", "correlation_id"}}`.
- [ ] Изменения схемы БД оформлены миграцией Alembic.
- [ ] Новые настройки читаются из окружения и добавлены в `.env.example`, секретов в коде и логах нет.
