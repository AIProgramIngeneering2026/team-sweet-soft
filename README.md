# Sweet Soft: сервис прогона матчей для бота StarCraft II
 
Сервис принимает задание на прогон (серия реплеев, сравнение версий бота, выгрузка результатов ладдера AI Arena), выполняет его и хранит результаты. Он отвечает на вопрос «новая версия бота лучше предыдущей?» по цифрам.

## Какую проблему решает и для кого
 
Мы пишем бота для StarCraft II. Чтобы понять, стал ли он лучше, его приходится гонять сериями матчей и сравнивать версии вручную: собирать реплеи, считать победы по картам и соперникам, переносить цифры в таблицу, отдельно заходить за результатами ладдера на AI Arena.
 
Сервис автоматизирует эту рутину. Пользователь это разработчик бота: он ставит задание на прогон, а сервис выполняет его, сохраняет результат и историю и дает посмотреть итог через HTTP API.

## Что входит в систему
 
- HTTP API (FastAPI, OpenAPI 3) для создания, просмотра и отмены прогонов.
- Исполнители с общим контрактом `validate(params)` и `run(params) -> ToolResult`:
  - `replay_stats` разбирает реплеи;
  - `series_summary` считает процент побед по серии;
  - `ab_compare` сравнивает две серии, то есть две версии бота;
  - `arena_sync` забирает результаты ладдера с AI Arena;
  - `local_match` запускает матчи против встроенного ИИ (по желанию, отдельный профиль).
- Хранилище: прогоны, история переходов, результаты, данные о реплеях (PostgreSQL, миграции Alembic).
- Адаптер API AI Arena и fake-сервер AI Arena для тестов.
- Запуск одной командой через Docker Compose.

## Что в систему не входит
 
- **Сам бот.** Для сервиса бот это просто zip-архив. Сервис не содержит логики бота, не обучает и не улучшает его.
- **Клиент StarCraft II.** Для работы сервиса он не нужен. Только `local_match` требует клиента, поэтому вынесен в отдельный профиль Compose и по умолчанию выключен.
- **Сама AI Arena.** Сервис только забирает с нее результаты через адаптер.

## Как это работает
 
Единица работы это прогон (Job, в API `/runs`). Он проходит состояния `created → queued → running → done / partial / failed / cancelled`. Разрешенные переходы и правила отмены описаны в [docs/requirements.md](docs/requirements.md#жизненный-цикл-job).
 
API:
 
| Метод | Назначение |
| --- | --- |
| `POST /runs` | создать прогон (идемпотентно по заголовку `Idempotency-Key`) |
| `GET /runs/{id}` | статус, результат и история переходов |
| `GET /runs` | список прогонов |
| `POST /runs/{id}/cancel` | отменить прогон |
| `GET /tools` | список доступных исполнителей |
| `GET /health` | состояние сервиса, включая проверку БД |
 
Все ошибки приходят в одном формате: `{"error": {"code", "message", "correlation_id"}}`.

Полный контракт API: [docs/api/openapi.yaml](docs/api/openapi.yaml). Как работает повторный запрос с `Idempotency-Key`: [ADR-0001](docs/adr/0001-idempotency-key.md).
